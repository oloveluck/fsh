9.3

fsh: FHIR Shorthand🔗

FHIR, the standard health systems use to exchange data, describes a lab result or a patient in general terms. Almost every field is optional, so that one kind of record, the Observation, can hold a blood pressure in one clinic and a genetic finding in another. People who actually exchange data have to say more: "here, a lab result always names its patient, is final, and carries its value as a number with a unit". A set of rules like that is called a profile. A profile tells a sender what to send and a receiver what to expect, and it lets a program decide whether a record is acceptable.

A profile is itself a FHIR resource, and written out as JSON it is long and hard to read. So people write profiles in FHIR Shorthand (FSH), an HL7 standard: a small text language with one line per rule. FSH also covers what a profile needs around it: the sets of codes a field may hold, fields FHIR does not have, and instances, which are examples of the data itself. Profiles, code sets and examples published together for one purpose are an Implementation Guide; US Core and the International Patient Summary are two.

This package is a compiler for FSH. It turns .fsh files into the FHIR resources they stand for. It checks every example against the profiles and reports each broken rule at the FSH line that caused it. It also goes the other way, from FHIR JSON back to FSH. It reads the same files as SUSHI, the compiler HL7 maintains and most guides are built with, so a project written for SUSHI can be checked here as it is.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Write a rule for your data and see whether an example passes: A first example.

  • Find a mistake where it is: a misspelt field, an example that breaks its profile, a unit written wrongly are each reported at their line, usually with the fix (What check checks).

  • Build on a published guide: start from US Core’s patient instead of FHIR’s, and be held to its rules too (Projects and Implementation Guides).

  • Get the FHIR JSON, or a package of it, to load into a server or hand to another tool (The FHIR JSON, and a package).

  • Turn FHIR JSON you already have into FSH, to read it or to keep editing it as text (FHIR JSON back to FSH).

  • Use a profile from a program: a .fsh file is a module a Racket program can require (As a module, from Racket).

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco fsh (or fsh, if you built the standalone tools).

2. Write a profile and an example of it. Make a folder, clinic/, and in it a file lab.fsh. The profile says what an HbA1c result (a blood test used to follow diabetes) must look like in this clinic; the instance is one such result.

Alias: $loinc = http://loinc.org

 

Profile: HbA1cResult

Parent: Observation

Id: hba1c-result

Title: "HbA1c result"

Description: "A final HbA1c result that names its patient and has a measured value."

* status = #final

* code = $loinc#4548-4

* subject 1..1

* value[x] 1..1

* value[x] only Quantity

 

Instance: ann-hba1c

InstanceOf: HbA1cResult

Description: "Ann's HbA1c of 7.2 %"

* status = #final

* code = $loinc#4548-4

* subject = Reference(Patient/ann)

* valueQuantity = 7.2 '%'

Reading it from the top:

  • Alias gives a short name to a long address. LOINC is the catalogue of codes for lab tests; $loinc#4548-4 is "code 4548-4 from LOINC", the code for HbA1c.

  • Profile starts a set of rules and names it. Parent: Observation says the rules are about FHIR’s Observation, the kind of record a measurement is kept in. Id is the short name it is published under.

  • Each line that starts with * is one rule. * status = #final fixes a value: only final results. * subject 1..1 is a count, "at least one, at most one": the result must name its patient. The last two rules say there must be a value and that it must be a Quantity, a number with a unit. (value[x] is FHIR’s way of writing a field that can hold several kinds of value.)

  • Instance starts an example: a real record, written field by field. InstanceOf: HbA1cResult claims that it follows the profile. Because the value is a Quantity, the field is written valueQuantity; the unit goes in single quotes.

3. Check it.

$ raco fsh check clinic/

fsh check: 1 example, 0 with errors; 0 errors, 0 warnings

  canonical: http://example.org (default; a sushi-config.yaml beside the files sets it: `canonical: http://…`)

check compiled the file and then held the example to the profile: one example, nothing wrong. The second line is about names. Every definition is published under a web address, its canonical url; with nothing to say otherwise, this profile is http://example.org/StructureDefinition/hba1c-result. Projects and Implementation Guides shows how to set your own.

4. Make a mistake. Change the example’s status to #preliminary and check again:

$ raco fsh check clinic/

clinic/lab.fsh:17:3: fsh validate error: instance ann-hba1c: Observation.status: value does not match required pattern "final" (constrained by profile HbA1cResult at line 8)

 17 | * status = #preliminary

    |   ^^^^^^

fsh check: 1 example, 1 with errors; 1 error, 0 warnings

  canonical: http://example.org (default; a sushi-config.yaml beside the files sets it: `canonical: http://…`)

The message has three parts: where the bad value was written (line 17, with a marker under it), what is wrong with it (the status is not final), and which rule of the profile says so (line 8). The command ends with exit status 1, so a script can tell. Put #final back.

5. Get the FHIR. Without check, the command writes the resources as JSON files:

$ raco fsh clinic/

  StructureDefinition-hba1c-result.json

  Observation-ann-hba1c.json

fsh: wrote 2 artifact(s) to clinic/fsh-generated

The first file is the profile as FHIR knows it, a StructureDefinition. The second is the example as an ordinary FHIR record:

{"code":{"coding":[{"code":"4548-4","system":"http://loinc.org"}]},"id":"ann-hba1c",

"meta":{"profile":["http://example.org/StructureDefinition/hba1c-result"]},

"resourceType":"Observation","status":"final","subject":{"reference":"Patient/ann"},

"valueQuantity":{"code":"%","system":"http://unitsofmeasure.org","unit":"%","value":7.2}}

(The file is one line; it is broken here to fit.) Any FHIR server or validator can read both.

3 Writing FSH🔗

This section goes through the parts of the language you will use first, each with an example. The full language is described in the FSH reference, and FSH School has tutorials.

3.1 The shape of a file🔗

A file is a list of entities. Each starts with a line saying what it is and what it is called, then a few keyword lines (Parent:, Id:, Title:, Description:), then its rules, one per *. Comments are // to the end of the line, or /* … */. A blank line between entities is customary.

entity

  

what it defines

Profile

  

rules for one kind of record

Instance

  

one record: an example, or a definition written out field by field

ValueSet

  

a set of codes a field may hold

CodeSystem

  

codes of your own

Extension

  

a field FHIR does not have

Invariant

  

a rule written as a test, used by a profile

RuleSet

  

rules to reuse in several places

Alias

  

a short name for an address

Logical

  

a data structure that is not a FHIR resource, such as a form

Resource

  

a new kind of resource

Mapping

  

how a profile's fields correspond to another standard's

All the files in one folder (and its subfolders) are one project: an entity in one file can use an entity in another.

3.2 Profiles: rules for a kind of record🔗

A profile starts from a parent and narrows it. The parent is a FHIR type (Patient, Observation) or another profile, yours or a published one. Every rule begins with a path, the name of the field it is about; a field inside a field is written with a dot (name.family).

rule

  

example

  

meaning

count

  

* subject 1..1

  

how many: at least 1, at most 1

flag

  

* subject 1..1 MS

  

MS: a system must be able to handle this field

fixed value

  

* code = $loinc#85354-9 "Blood pressure panel"

  

the field must contain this

exact value

  

* status = #final (exactly)

  

the field must be this and nothing more

type

  

* value[x] only Quantity or CodeableConcept

  

which kinds of value are allowed

reference

  

* subject only Reference(Patient)

  

what a link may point to

code set

  

* category from ObservationCategoryCodes (required)

  

the codes allowed (a binding)

slices

  

* component contains systolic 1..1 and diastolic 1..1

  

named entries of a list

invariant

  

* obeys bp-1

  

a test the record must pass

rule set

  

* insert CommonMetadata

  

the rules of a RuleSet, here

anything else

  

* code ^short = "What was measured"

  

set a property of the field's definition

A code is written system#code, with the system’s address or an alias for it; a code whose system is already known from the field is just #final.

A path the parent does not have is caught when the profile is compiled, with the name you probably meant:

$ raco fsh clinic/

clinic/lab.fsh:10:3: fsh compile error: profile: HbA1cResult: `subjct` is not an element of Observation (did you mean `subject`?)

 10 | * subjct 1..1

    |   ^^^^^^

3.3 Instances: examples of the data🔗

An instance is a record written one field per rule. It is how you show what conforming data looks like, and it is what check tests your profiles with: a profile nobody has tried on an example is a guess.

Instance: ann-hba1c

InstanceOf: HbA1cResult

* status = #final

* code = $loinc#4548-4

* subject = Reference(Patient/ann)

* valueQuantity = 7.2 '%'

  • What it is an instance of. InstanceOf names a profile or a plain FHIR type. With a profile, the record says so itself (in meta.profile) and is checked against it. Fixed values the profile requires are filled in for you when you leave them out.

  • Values. Text in double quotes, "Lee"; a date as text, "1974-12-25"; a code, #final or $loinc#4548-4; a number with a unit, 7.2 '%' or 150 'mm[Hg]'; a link to another record, Reference(Patient/ann).

  • Lists. A field that repeats is indexed: name[0].given, name[1].given. [+] means "the next entry" and [=] "the same entry as the line above", so you need not count. With no index you are writing the first entry.

  • Fields with several possible types. Where FHIR writes value[x], an instance names the type it uses: valueQuantity, valueString, effectiveDateTime.

  • What it is for. Usage: #example is the default. Usage: #definition marks a record that is part of the guide itself (a search parameter, a server’s capability statement), and Usage: #inline one that only exists inside another.

A required field left out is reported at the instance’s first line, since no rule wrote it:

clinic/lab.fsh:14:1: fsh validate error: instance ann-hba1c: Observation.subject: minimum required = 1, but found 0 (no rule of ann-hba1c writes `subject`) (constrained by profile HbA1cResult at line 10)

 14 | Instance: ann-hba1c

    | ^^^^^^^^^

3.4 Value sets and code systems: which codes are allowed🔗

A coded field (a visit’s type, a patient’s sex) holds a code from some catalogue. A code system is a catalogue; a value set is a selection from one or more catalogues; a binding ties a field to a value set.

CodeSystem: VisitKind

Id: visit-kind

Title: "Kinds of visit"

* #walk-in "Walk-in"

* #booked "Booked"

* #phone "By telephone"

 

ValueSet: InPersonVisits

Id: in-person-visits

Title: "Visits in person"

* VisitKind#walk-in

* VisitKind#booked

 

Profile: ClinicVisit

Parent: Encounter

Id: clinic-visit

* type 1..1

* type from InPersonVisits (required)

The code system defines three codes of the clinic’s own. The value set picks two of them. The profile’s last rule binds the visit’s type to that value set. The word in parentheses is the binding’s strength: required (only these codes), extensible (these, unless none fits), preferred or example.

A value set can also be defined by a rule over a large catalogue instead of a list: * include codes from system http://snomed.info/sct where concept is-a #44054006.

FHIR’s own required code sets are checked on every example. An Observation whose status is misspelt, * status = #finl, gets a message that lists what is allowed:

codes/typo.fsh:3:3: fsh validate error: instance typo: Observation.status: code `finl` not in required value set http://hl7.org/fhir/ValueSet/observation-status (did you mean `final`?); it holds amended, cancelled, corrected, entered-in-error, final, preliminary, registered, unknown

 3 | * status = #finl

   |   ^^^^^^

A binding your own profile adds is written into the profile, but check does not yet test an example’s code against it (Limits).

3.5 Invariants: a rule as a test🔗

Some rules are not about one field: "a heart rate is between 20 and 250". An invariant states such a rule twice, in words for people and as a FHIRPath expression for the computer. A profile adopts it with obeys.

Profile: HeartRate

Parent: Observation

Id: heart-rate

* code = http://loinc.org#8867-4

* value[x] only Quantity

* obeys hr-range

 

Invariant: hr-range

Description: "A heart rate is between 20 and 250 /min"

Expression: "value.ofType(Quantity).value >= 20 and value.ofType(Quantity).value <= 250"

Severity: #error

 

Instance: fast

InstanceOf: HeartRate

* status = #final

* code = http://loinc.org#8867-4

* valueQuantity = 300 '/min'

$ raco fsh check heart/

heart/hr.fsh:17:3: fsh validate error: instance fast: Observation: hr-range: A heart rate is between 20 and 250 /min (found valueQuantity.value = 300)

 17 | * valueQuantity = 300 '/min'

    |   ^^^^^^^^^^^^^

fsh check: 1 example, 1 with errors; 1 error, 0 warnings

  …

The message gives the invariant’s own words, then what it found, at the line that wrote it.

3.6 Slices: rules for one entry of a list🔗

A blood pressure is one record with two measurements in a list, systolic and diastolic. To make rules about "the systolic entry" you first have to say how to recognise it. That is slicing: the list is cut into named slices, told apart by some field, here each entry’s code.

Alias: $loinc = http://loinc.org

 

Profile: BloodPressure

Parent: Observation

Id: blood-pressure

* code = $loinc#85354-9

* component ^slicing.discriminator.type = #pattern

* component ^slicing.discriminator.path = "code"

* component ^slicing.rules = #open

* component contains systolic 1..1 and diastolic 1..1

* component[systolic].code = $loinc#8480-6

* component[systolic].value[x] only Quantity

* component[diastolic].code = $loinc#8462-4

* component[diastolic].value[x] only Quantity

 

Instance: reading-1

InstanceOf: BloodPressure

* status = #final

* code = $loinc#85354-9

* component[systolic].valueQuantity = 150 'mm[Hg]'

* component[diastolic].valueString = "ninety"

The three ^slicing lines say the entries are told apart by their code and that other entries are allowed (#open). contains names the slices and says each must be there once. After that component[systolic] is a path like any other, in the profile and in the instance. The instance does not repeat the slices’ codes: the compiler fills them in from the profile.

$ raco fsh check bp/

bp/bp.fsh:21:3: fsh validate error: instance reading-1: Observation.component.value[x]: valueString is not allowed in slice 'diastolic' (value[x]: Quantity) (constrained by profile BloodPressure at line 14)

 21 | * component[diastolic].valueString = "ninety"

    |   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

fsh check: 1 example, 1 with errors; 1 error, 0 warnings

  …

3.7 Extensions: a field FHIR does not have🔗

When the data has something FHIR has no field for, you define an extension and add it to a profile under a name of your choosing.

Extension: PreferredPharmacy

Id: preferred-pharmacy

Title: "Preferred pharmacy"

Description: "The pharmacy the patient wants prescriptions sent to."

* value[x] only Reference(Organization)

 

Profile: ClinicPatient

Parent: Patient

Id: clinic-patient

* extension contains PreferredPharmacy named pharmacy 0..1

* name 1..*

 

Instance: ann

InstanceOf: ClinicPatient

* name.family = "Lee"

* name.given = "Ann"

* extension[pharmacy].valueReference = Reference(Organization/corner-pharmacy)

In the compiled record the extension appears under its own address, which is how any FHIR system recognises it:

"extension": [{"url": "http://example.org/StructureDefinition/preferred-pharmacy",

    "valueReference": {"reference": "Organization/corner-pharmacy"}}]

3.8 Saying it once: aliases and rule sets🔗

An Alias names an address. A RuleSet names a group of rules, which * insert puts wherever they are wanted. A rule set can take parameters, written in braces where they are used, which makes many similar examples short:

Alias: $loinc = http://loinc.org

 

RuleSet: HbA1c(patient, date, value)

* status = #final

* code = $loinc#4548-4

* subject = Reference(Patient/{patient})

* effectiveDateTime = "{date}"

* valueQuantity = {value} '%'

 

Instance: ann-march

InstanceOf: Observation

* insert HbA1c(ann, 2025-03-01, 7.2)

 

Instance: ann-september

InstanceOf: Observation

* insert HbA1c(ann, 2025-09-01, 9.4)

Inserting a rule set the project does not define is an error at the insert: RuleSet `Hba1c` not found: no RuleSet of that name is in the project.

4 Projects and Implementation Guides🔗

A folder of .fsh files is a project. It becomes an Implementation Guide when it says what it is called, where it is published and what it builds on. That is the job of one more file.

4.1 The guide file: sushi-config.yaml🔗

sushi-config.yaml sits beside the .fsh files (or one or two folders above them). The name comes from SUSHI, which reads the same file. A small one:

id: example.clinic

canonical: http://example.org/clinic

name: ClinicGuide

title: Clinic Guide

status: draft

version: 0.1.0

fhirVersion: 4.0.1

key

  

what it says

id

  

the guide's package name, the name it is distributed under

canonical

  

the base of every address the project defines

name

  

a name a program can use: letters and digits

title

  

a name for people

status

  

draft, active or retired; your definitions carry it too

version

  

the guide's version

fhirVersion

  

which FHIR the project is written for: 4.0.1 (R4) or 5.0.0 (R5)

dependencies

  

the published guides the project builds on, each with its version

license, description, publisher

  

carried into the package

With this file in clinic/, the profile of the first example is compiled for FHIR R4 and published as http://example.org/clinic/StructureDefinition/hba1c-result:

$ raco fsh check clinic/

fsh check: 1 example, 0 with errors; 0 errors, 0 warnings

  canonical: http://example.org/clinic (…/clinic/sushi-config.yaml)

Without the file, a project is compiled for FHIR R5 under http://example.org; --canonical and --fhir-version on the command line set either one, and override the file.

The guide file is a language of its own here, in a small way. FHIR has a resource that describes a guide, the ImplementationGuide: its name and version, what it depends on, and a list of everything it defines, marking which records are examples and of which profile. The file compiles to that resource, and a mistake in the file is reported at its line, as in the other languages:

sushi-config.yaml:2:1: ig check error: status `actve` is not draft, active, retired or unknown (did you mean `active`?)

That compilation is used where a guide is kept and versioned as a whole: in a fhir-mcp workspace, where the guide file also sets the FHIR version, the packages and the rules for every other language in the workspace, and from Racket (fsh/ig). The command line reads the file for the facts above and does not write the ImplementationGuide resource. The details, including two more keys (global, a profile every record of a type is held to, and parameters), storing a guide, releasing a version and pinning the versions of what it uses, are in ig-guide.md in the repository; raco fhir guide ig prints it.

4.2 Building on a published guide🔗

Most guides do not start from bare FHIR. In the United States a patient profile usually starts from US Core’s. Name the guide under dependencies and its profiles, extensions and value sets can be used by name:

id: example.uscore

canonical: http://example.org/uscore

version: 0.1.0

fhirVersion: 4.0.1

dependencies:

  hl7.fhir.us.core: 6.1.0

Profile: ClinicPatient

Parent: USCorePatientProfile

Id: clinic-patient

* birthDate 1..1

 

Instance: ann

InstanceOf: ClinicPatient

* name.family = "Lee"

* gender = #female

* birthDate = "1974-12-25"

Your profile adds one rule, and inherits all of its parent’s. The example is held to both:

$ raco fsh check uscore/

uscore/patient.fsh:6:1: fsh validate error: instance ann: Patient.identifier: minimum required = 1, but found 0 (no rule of ann writes `identifier`)

 6 | Instance: ann

   | ^^^^^^^^^

fsh check: 1 example, 1 with errors; 1 error, 0 warnings

  …

US Core requires every patient to have an identifier, so the example needs one.

A dependency is a package: the .tgz file a guide is distributed as. Packages are not downloaded for you. A dependency hl7.fhir.us.core: 6.1.0 is looked for as the file hl7.fhir.us.core-6.1.0.tgz, among the packages that come with the tools (US Core 6.1.0 and 8.0.0, mCODE 4.0.0, Genomics Reporting 2.0.0, CRMI 2.0.0 and CQF Measures 5.0.0) and then in the folders named by the environment variable FHIR_PACKAGE_PATH. Packages are published at packages.fhir.org. When one is missing, raco fsh says so and goes on, and a parent or type that needed it is then reported as not found:

fsh: dependency no.such.package 1.0.0 not found (looked for no.such.package-1.0.0.tgz in fhir-spec); its profiles will not resolve

4.3 The FHIR JSON, and a package🔗

raco fsh clinic/ writes one JSON file per resource into clinic/fsh-generated/ (-o names another folder). If anything fails to compile, the problems are printed and nothing is written.

--pack also writes the project as a package, the form in which a guide is handed to other tools. It needs the guide file, for the package’s name and version:

$ raco fsh clinic/ --pack clinic-0.1.0.tgz

fsh: packed 2 resource(s) into …/clinic-0.1.0.tgz

  StructureDefinition-hba1c-result.json

  Observation-ann-hba1c.json

fsh: wrote 2 artifact(s) to clinic/fsh-generated

Inside the package the definitions are in package/, the examples in package/example/, and package/package.json carries the name, version and dependencies. Without a file name the package is written as <id>-<version>.tgz in the current folder.

A package that contains a description of a server (a CapabilityStatement) can be run as one: raco fhir-server serve-ig clinic-0.1.0.tgz starts a FHIR server that accepts what the guide describes. See fhir-server.

5 Running it🔗

5.1 Command line🔗

raco fsh check clinic/

  

compile, then test every example against the profiles; each problem at its FSH line

raco fsh check bad/ --context profiles/

  

check one folder against another folder’s definitions; repeat --context for more

raco fsh check clinic/ --capability <id>

  

also report what a server generated from the guide would not do

raco fsh clinic/

  

compile every .fsh under the folder to clinic/fsh-generated/<Type>-<id>.json

raco fsh clinic/ -o out/

  

the same, into another folder

raco fsh clinic/ --pack [out.tgz]

  

also write the package

raco fsh clinic/ --snapshot

  

also write each profile's snapshot (see below)

raco fsh lab.fsh

  

one file

raco fsh --decompile a.json b.json

  

FHIR JSON to FSH, printed

Other options: --fhir-version 4.0.1|5.0.0 and --canonical <url>, for a project without a guide file or to override it; --format text|json|outcome, how problems are reported. text is for a person and goes to the error stream; json and outcome (a FHIR OperationOutcome) go to standard output for a program:

{"diagnostics":[{"column":1,"lang":"fsh","line":1,"message":"instance no-value: Observation.value[x]: minimum required = 1, but found 0 (no rule of no-value writes `value`) (constrained by profile HbA1cResult at profiles/lab.fsh:11:3)","phase":"validate","position":1,"severity":"error","source":"bad/no-value.fsh","span":9}]}

The command exits with 0 when all is well, 1 when there is an error in the FSH and 2 when it was called wrongly (a folder that is not there, an unknown option).

A profile is normally written as its differential: only what it changes in its parent. --snapshot adds the snapshot, the whole resulting definition with every field, which some tools want.

5.2 What check checks🔗

raco fsh check does everything this package knows how to do with a project, and reports all of it in one run:

  • The text parses. A parse error says what was unexpected, and where it can, what to write instead: unexpected sequence `%` — a quantity's UCUM unit is quoted: `7.2 '%'`.

  • The definitions compile. A field the parent does not have, a Parent or InstanceOf nothing defines, a rule set that is not there, two definitions with the same id. Each is reported and the rest still compiles.

  • Every example is valid: against FHIR’s own definition of its type, against the profile it is an instance of, and against that profile’s parents, a dependency’s included. That covers counts, fixed values, types, FHIR’s required code sets, slices, invariants, the form of dates and other simple values, and units.

  • Maps, if the project has any (Maps in a project).

  • A server, with --capability (below).

A problem in an example is placed on the rule of the instance that wrote the offending value, and names the rule of the profile that it breaks. When the cause is something missing, there is no such rule, so the problem is placed on the instance’s first line.

Examples that are meant to fail. It is useful to keep examples the profile should refuse. Kept in the project they would make every check fail, so put them in a folder of their own and check it against the project’s definitions:

$ raco fsh check bad/ --context profiles/

bad/no-value.fsh:1:1: fsh validate error: instance no-value: Observation.value[x]: minimum required = 1, but found 0 (no rule of no-value writes `value`) (constrained by profile HbA1cResult at profiles/lab.fsh:11:3)

 1 | Instance: no-value

   | ^^^^^^^^^

fsh check: 1 example, 1 with errors; 1 error, 0 warnings

  …

The context folder’s definitions are used; its own examples and problems are left out. If you forget the option, the message tells you: (`HbA1cResult` is defined in profiles/lab.fsh: check with `--context profiles`).

A server’s requirements. A guide can include a CapabilityStatement: a list of what a server that follows the guide must do (which records it serves, which searches and operations). --capability <id> generates such a server from the project and reports each requirement it would not meet. It needs the guide file and the fhir-server package.

$ raco fsh check clinic/ --capability clinic-server

clinic/server.fsh:1:1: fsh server error: clinic-server: SHALL Observation stats not met: operation not implemented

 1 | Instance: clinic-server

   | ^^^^^^^^^

fsh check: 1 example, 0 with errors; 1 error, 0 warnings

  …

5.3 FHIR JSON back to FSH🔗

You may have FHIR JSON and no FSH: a profile somebody published, a record from a server. --decompile writes it as FSH, to read or to go on editing as text. (The HL7 tool that does this is called GoFSH.)

$ raco fsh --decompile clinic/fsh-generated/Observation-ann-hba1c.json

Instance: ann-hba1c

InstanceOf: Observation

Usage: #example

* code = http://loinc.org#4548-4

* meta.profile[0] = "http://example.org/clinic/StructureDefinition/hba1c-result"

* status = #final

* subject = Reference(Patient/ann)

* valueQuantity = 7.2 '%'

Give it several files and you get one FSH document. The aim is FSH that compiles back to exactly the JSON it came from. Where a short form would lose something, the longer form is written: the profile of the first example comes back with its fixed values as ^ rules (* status ^patternCode = "final"), which mean the same as * status = #final.

5.4 As a module, from Racket🔗

A .fsh file whose first line is #lang fsh is a Racket module, so a program can require it and use what it defines. The file is compiled when the program is built: a misspelt field in a profile stops the build, at its line. (raco fsh reads a file with or without that first line.)

(require (only-in "lab.fsh" compiled canonical-of)
         (only-in fhir/conformance/operations ensure-valid))
(for/list ([r compiled]) (list (hash-ref r 'resourceType) (hash-ref r 'id)))
; '(("StructureDefinition" "hba1c-result") ("Observation" "ann-hba1c"))
(canonical-of "HbA1cResult")
; "http://example.org/StructureDefinition/hba1c-result"
(define reading (cadr compiled))
(ensure-valid reading #:profile (canonical-of "HbA1cResult"))
; returns the record; raises, listing the problems, when it is not valid

The module provides compiled (the resources as JSON values), resources (the same as typed nodes), document (the parsed entities) and canonical-of (a definition’s address, by its name or id). Requiring it also registers its profiles, value sets and code systems under their addresses, which is why ensure-valid above can find the profile. Like the command line, the module is compiled with the nearest sushi-config.yaml. Running the file, racket lab.fsh, prints its resources as JSON.

Building a module does not validate its examples; that needs the whole project. To have them checked on every test run, call the checker from a test:

(require fsh/check (only-in fhir/diagnostic diagnostic->string))
(map diagnostic->string (check-report-diagnostics (check-fsh-project "clinic/")))
; '() when every example is valid; else one line per problem

5.5 The pieces, from Racket🔗

The steps the command line does, one at a time. Load a FHIR version’s types first (fhir/r5/schemas or fhir/r4/schemas) when you compile text yourself; compile-project and check-fsh-project do that for you.

(require fhir/r5/schemas fsh/compile fsh/project fsh/check fsh/decompile)
(fsh->fhir text)                                   ; FSH text -> the resources, as JSON values
(define p (compile-project "clinic/"))             ; a project, with its sushi-config.yaml
(project-artifacts p)                              ; the resources
(project-diagnostics p)                            ; every problem, positioned
(check-report-diagnostics (check-fsh-project "clinic/"))  ; what raco fsh check reports
(fhir->fsh resource)                               ; a JSON value -> FSH text

5.6 Maps in a project🔗

A project may also hold .map files in the FHIR Mapping Language, which converts data from one structure to another (it needs the fml package). Their compiled form joins the package, and check checks each map against the project’s structures, runs it over the examples of its source structure and validates the results against its target; findings are placed in the map. The structure a map reads is often not FHIR at all but a form or a message, described with Logical:. An Instance: of a logical model is written like any other; name the model by its Id. The worked project is fhir-examples/examples/intake-maps.

6 In an editor, and for an AI agent🔗

  • In an editor. The family’s language server, fhir-lsp, underlines a file’s problems as you type, using the whole project. It lists a file’s entities, shows a field’s definition or a name’s declaration when you hover, jumps to a definition anywhere in the project, and completes keywords, parents and types, value sets after from, rule sets, invariants, flags and the fields available at a path.

  • For an agent. In an fhir-mcp workspace the FSH files are one project: writing a file answers its problems at their lines, every example is validated, and what the FSH defines is visible to the other languages by its address. The repository’s guide.md is the language written for an agent to read (fhir-mcp serves it as learn://fsh; raco fhir guide fsh prints it), ig-guide.md is the same for the guide file (learn://ig), and .claude/skills/fsh is the workflow for an agent using the command line.

7 Limits🔗

  • FHIR versions. R4 (4.0.1) and R5 (5.0.0).

  • Codes. An example’s codes are tested against the code sets FHIR itself requires (a status, a patient’s gender). A binding your own profile adds, whether to a value set of the project or of a package, is written into the profile, but check does not test an example’s code against it. Use a terminology service for that (fhir-tx).

  • Links are not followed. Reference(Patient/ann) is not checked to lead to a record that exists.

  • Packages are not downloaded. A dependency must already be on the machine (Building on a published guide).

  • The website of a guide is not built. The pages, menus and the readable summary inside each resource (its narrative) are the work of HL7’s IG Publisher. The command line does not write the ImplementationGuide resource either; fsh/ig and a fhir-mcp workspace do.

  • Snapshots are on request (--snapshot); the default output is the differential.

  • Not everything SUSHI writes is reproduced. For the published guides this is tested on, most resources come out identical to the published ones and a minority differ in details (How it is tested). An R5-only resource used in an R4 project is accepted and left as it is; the IG Publisher would convert it.

  • The decompiler writes plain FSH. It does not gather repeated addresses into aliases or repeated rules into rule sets, and it writes a profile’s fixed values as ^ rules.

  • Building a module is not checking it. Requiring a #lang fsh file compiles it and catches a misspelt field; only raco fsh check (or check-fsh-project) validates the examples.

8 Words used here🔗

  • Resource: one FHIR document, such as a Patient or an Observation, written as JSON.

  • Profile: a set of rules a resource must follow in some setting, on top of FHIR’s own. Compiled, it is a StructureDefinition resource.

  • Differential, snapshot: a profile written as only what it changes in its parent, or in full.

  • Instance: one record written in FSH, usually an example of a profile.

  • Entity, rule: an entity is one thing a file defines (a profile, an instance, a value set); a rule is one of its * lines.

  • Path: the name of a field inside a record, such as name.family or component[systolic].code.

  • Cardinality: how many times a field may appear, written min..max; * means any number.

  • Code system, value set, binding: a catalogue of codes (LOINC, SNOMED CT); a selection of codes; the rule tying a field to a value set.

  • Slice: a named entry of a list, recognised by one of its fields (the discriminator).

  • Extension: a field added to FHIR, identified by its address.

  • Invariant: a rule stated as a FHIRPath test; FHIRPath is FHIR’s small language for pointing inside a resource.

  • Canonical url: the web address that names a definition. It is a name; nothing needs to be served there.

  • Implementation Guide (IG): profiles, value sets and examples published together for one purpose. ImplementationGuide is the FHIR resource that describes one.

  • Package: the .tgz file a guide is distributed as.

  • SUSHI: HL7’s compiler for FSH, the reference for the language. sushi-config.yaml is the guide file it reads. GoFSH is HL7’s tool for the other direction, FHIR to FSH. The IG Publisher is HL7’s tool that turns SUSHI’s output into a guide’s website and package.

  • Logical model: a description of a data structure that is not a FHIR resource.

  • UCUM: the standard for writing units (mm[Hg], /min, %).

  • CapabilityStatement: the FHIR resource that lists what a server does or must do.

9 How it is tested🔗

Against published guides, not only its own examples. A guide’s FSH sources are compiled here and compared, resource by resource, with the package HL7 published from the same sources (built with SUSHI and the IG Publisher), leaving aside what only the Publisher adds.

  • Five guides compile from their own FSH with no errors. Of the resources that can be paired with the published ones: International Patient Summary 2.0.1, 94 of 114 identical and 108 with all the published content; mCODE 4.0.0, 311 of 349 and 339; Da Vinci Plan-Net 1.2.0, 84 of 109 and 99; Da Vinci HRex 1.1.0, 31 of 46 and 46; Genomics Reporting 2.0.0, 121 of 141 and 129.

  • The other direction: the published IPS and mCODE packages decompiled to FSH and compiled back. All 117 IPS resources come back identical, and 341 of mCODE’s 349.

  • The parser’s verdicts against SUSHI’s own test suite of 515 FSH texts: 514 agree, with no error missed and none reported where SUSHI reports none.

  • SUSHI’s 22 hand-written pairs of FSH and JSON all compile to their JSON and survive the round trip.

  • mCODE’s examples, compiled and packed here, all validate against the profiles compiled here, as they do against the published package.

The repository’s TESTING.md says what the remaining differences are and how to run the tests. To work on the compiler itself, install the packages from source with the repositories side by side, then run everything:

raco pkg install --link --auto ../fhir/fhir ../fhir/fhir-spec ../fhirpath ../vcl ../fhir/fhir-tx ../fhir/fhir-validation .

raco test .
